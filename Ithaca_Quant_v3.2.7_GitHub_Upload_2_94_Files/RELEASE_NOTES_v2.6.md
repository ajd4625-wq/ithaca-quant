# Ithaca Quant v2.6.0 — Accuracy Challenge & Friday Reports

## What is really new

1. **Dedicated stock ranking challenger:** `ithaca_quant/ranking_accuracy.py` trains a Logistic Regression probability model for future SPY-relative direction. Its input includes the existing point-in-time historical price, cross-sectional momentum, liquidity, early-trend, and 52-week features. It uses purged, chronologically separate fit/selection/audit periods. Only when Brier error improves by at least 1% versus a constant-probability baseline *and* the selected top quartile's positive-event rate beats the overall event rate by at least 2.5 percentage points on **both** selection and audit periods is the ranking challenger displayed as validated research. Otherwise the old ranking model remains primary. A successful audit does not guarantee future success. It does **not** automatically replace the model's return-price forecast or existing entry/exit colors.
2. **Measured high-confidence performance, not marketing:** Audits include overall directional accuracy, rank-top-quartile hit rate, Brier score, number of stock samples, independent decision dates, and the count/coverage of predictions with probability at least 70% or at most 30%. A reported 80% on a very small fraction of companies does not establish that the entire model has 80% accuracy. These are still retrospective evaluations; forward performance is tracked separately.
3. **Immutable real-time forecast ledger:** Continues recording predictions by ticker/as-of/horizon, one per key. Adds a `resolved_utc` timestamp upon first successful scoring against actual prices, never altering the original prediction. Existing SQLite and SQL tables migrate safely. The old resolved records without timestamps remain valid for lifetime metrics but are excluded from new weekly reports because their resolution date is unknown.
4. **Actual weekly accuracy scoreboard:** `ithaca_quant/weekly_reports.py` calculates only newly resolved outcomes in the trailing Friday-to-Friday reporting window. Reports direction hit rate, model and predict-zero MAE, number evaluated, an optional positive-signal hit rate, and metrics per horizon. Reports with fewer than 30 resolved predictions across at least five prediction dates are clearly marked as insufficient evidence; more data can still be highly correlated.
5. **Friday schedule:** `.github/workflows/ithaca-weekly-report.yml` triggers every Friday at 4:00 PM **America/New_York** using timezone-aware GitHub Actions scheduling (4 PM EST in winter / 4 PM EDT in summer). Provider delays and GitHub Actions scheduling can delay reports. The job refreshes prices, reconciles newly matured forecasts, saves the scorecard in the shared database, and emails it **if configured**. At 4 PM market close data may be delayed, so pending outcomes are NOT counted as errors or made up.
6. **Daily collection outside the browser:** `.github/workflows/ithaca-daily-forecasts.yml` runs every weekday at 4:30 PM ET to record 5- and 20-session predictions for up to 60 configured symbols (`ITHACA_REFRESH_TICKERS`) and resolve matured outcomes in a shared PostgreSQL store. Requires at least 5 configured tickers. Unavailable or stale market data causes safe skipped runs. No trading orders are placed.
7. **Notifications:** The dashboard shows a short in-app toast and a sidebar notice when a Friday report is saved, and the Accuracy Lab shows a ready report, a download button, previews, and resolved prediction counts. An optional Friday email is the off-site notification. No browser push notifications or account-wide email signup is implemented.
8. **Secure optional configuration:** The workers require `ITHACA_DATABASE_URL` in **both** GitHub Actions Secrets and Streamlit Secrets to share the same database. To enable emails set GitHub Actions secrets `ITHACA_REPORT_EMAIL_TO`, `ITHACA_SMTP_HOST`, `ITHACA_SMTP_USER`, `ITHACA_SMTP_PASSWORD`, optional `ITHACA_SMTP_PORT` (465) and `ITHACA_REPORT_EMAIL_FROM`. TLS-only SMTP; no passwords are embedded in the app. Set `ITHACA_REFRESH_TICKERS` for daily predictions. No credentials means no outgoing email. Both workflows must be saved at `.github/workflows/` in the **repo root**, even when the app is in a subfolder. Workflows detect the v2.6.0 application folder automatically.

## Accuracy limitations

- **There is no verified 80% live-market hit rate.** Code functionality tests do not measure predictive success. Do not relabel backtests, synthetic tests, or small high-confidence subsets as overall accuracy.
- Historical SEC, news, and Form 4 data remain subject to availability of correctly timestamped prior information. Historical Form 4 activity is not automatically injected into the rank-classifier (Form 4 is still a separate research tab). There is insufficient evidence to claim it raises precision.
- Price-based ranking candidates that fail the independent accuracy gates are withheld. The original model is unchanged until audited evidence demonstrates improvement.
- Daily and weekly scheduled reports require a **durable database**, a public market-data feed, GitHub Actions workflows and permissions, and for email, SMTP secrets. No automatic delivery can be guaranteed until those are configured and live tested.
- Forecasts are SPY-relative; positive-direction accuracy is different from predicting absolute price direction or a profitable trade. Transaction costs and actual fill prices are not captured by the weekly direction metric.

## Installation

1. Replace your current working Streamlit app folder with the contents of the ZIP (including `app.py`, `streamlit_app.py`, and the entire `ithaca_quant/` package), preserving the working deployment's main-file path.
2. Copy `.github/workflows/ithaca-daily-forecasts.yml` and `.github/workflows/ithaca-weekly-report.yml` to the **repository root** `.github/workflows/` directory. This is a separate step if your app is nested.
3. Set the same authorized `ITHACA_DATABASE_URL` in Streamlit Secrets and GitHub Actions Secrets. Configure `ITHACA_REFRESH_TICKERS` (at least five comma-separated stock symbols).
4. For Friday email set the optional SMTP secrets. You can manually trigger each GitHub workflow through GitHub Actions to verify that it produces a stored report and an email; don't assume configuration works until tested.
5. In the app open **Accuracy Lab** to preview your report and click **Train & audit alternative ranking model** to run the accuracy challenge on real data. Existing scanner, current-news event deduplication, screenshot portfolio import, and SEC Form 4 tab are preserved.
