# Ithaca Quant v2.5.3 — Whole-leaderboard news coverage and one event per catalyst

## 1. Every modeled leaderboard stock enters an automatic news queue
Before this release, only the top 12 companies were automatically checked; other companies remained marked unchecked. The app now queues **every company that remains in the modeled leaderboard after the selected filters**. This is distinct from the entire exchange listing: a ticker not included in the model's scan/shortlist cannot have a ranked-stock signal. Every included ticker gets a news-check attempt over successive active 60-second cycles.

Up to **24 companies per cycle** are fetched with a maximum of **three concurrent ticker requests**. The top 24 companies receive priority when their cached results are older than **15 minutes**; the rest use a **24-hour cache** to let the queue reach the full filtered universe without repeatedly rechecking the top candidates. Completed, current reviews are reused on page reruns and by other sessions on the same local server instance. The leaderboard displays **checked / total**, a progress bar, unique event counts, and individual provider errors. Unchecked, failed, or stale companies cannot get green/dark-green entry clearance. This check does not continue while Streamlit is sleeping or when its active session stops.

## 2. More outlets without a request for each outlet
Leaderboard searches use **one Google News RSS query per ticker** with an eligible 45-day lookback and publisher attribution. Google News can return Reuters, Yahoo Finance, CNBC, Bloomberg, MarketWatch, and other indexed sources. It does **not** guarantee that every publisher or article is indexed. The existing publisher-specific individual-stock search remains available. One ticker query avoids the enormous request volume of querying nine publishers for thousands of stocks.

## 3. Deduplicate *events*, not just identical titles
The event clustering groups same-company headlines using the event category (acquisition, earnings, guidance, analyst, regulatory, contract, product, other), overlapping meaningful keywords, announcement proximity, reporting quarter and named deal target where available. For example, “Acme to acquire Beta” and “Acme buys Beta” are counted as **one acquisition event**, not two. An Acme acquisition of Delta is a different event even if both were reported on the same day. Q3 earnings and Q4 earnings are separate. Heuristic matching is conservative for product, contract, and regulatory news; it may still split true duplicates or merge similar independent headlines, so review links.

The chosen representative headline retains publisher and source link; event objects also retain a list of publishers and how many headlines were grouped. The leaderboard now shows **“Unique news events (7d),” “Reporting outlets (latest event),” and “Reports grouped into one event”** so you can verify exactly why five matching stories count as one catalyst. Multiple independent outlets can support the same event, but they **do not multiply its sentiment vote, event count, or deal warning**.

## 4. Existing forecasts and evidence integrity
Deduplication is applied to current news sentiment, acquisition reviews, and historically archived training feature calculations. When computing historical features, only headlines first seen by that decision date are eligible, avoiding future-data leakage. This release **does not retrain the main forecasting model** or claim improved investment accuracy. Additional news coverage is research context unless a point-in-time feature set has passed the model's existing validation gate.

## 5. Data availability and limits
Provider errors (including throttling) do not create false “no news” results. Errors retry after ~15 minutes. Successful searches that return no eligible article count as checked for that batch, **not** as proof no event occurred. The app can only screen for events available from indexed sources. The local SQLite news queue survives Streamlit reruns but **is not guaranteed to survive Streamlit Community Cloud restarts**. No server-side worker runs when the app is asleep. A scan of hundreds of modeled tickers can take many active minutes to complete; the cache is intentionally longer for the broad pool to reduce throttling.

## 6. Deployment
Replace the matching v2.5.2 application files in your existing working GitHub folder with this complete v2.5.3 release: `app.py`, `streamlit_app.py`, `requirements.txt`, the entire `ithaca_quant` package (including `universe_news.py` and `news_dedupe.py`), tests, and docs. **Keep your current Streamlit main-file path unchanged**. Don't create an extra wrapper directory or edit version labels separately.
