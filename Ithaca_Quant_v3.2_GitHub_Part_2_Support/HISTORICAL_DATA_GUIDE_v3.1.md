# Ithaca Quant v3.1 — Historical data integrity and provider import

## What v3.1 can and cannot establish

The importer validates **schema, chronology, security identity, immutable input file digests, observed price coverage, and archived delisting payoffs**. This prevents specific historical-data defects from entering the model unnoticed.

**It does not obtain or independently authenticate a complete U.S. delisted-security database.** A user-written `provider` entry, `historical_archive` marker, or SHA-256 hash does not prove a vendor's dataset was accurate or complete. Results are labeled **source-declared, integrity-checked**, not institutionally certified. The normal Yahoo/current-listings screen is still survivor-biased for historical tests and is not upgraded to PIT by checking a box.

Use a vendor-provided historical security-master + PIT membership + price/total-return export. Potential providers for independently sourced datasets include **CRSP via WRDS** or **Norgate Data** (depending on license and coverage). The **SEC EDGAR Companyfacts API** provides original filing dates and historical values for many U.S. issuers, but is **not** a historical exchange membership or delisting-return source. Respect data-license terms; do not publish licensed extracts in GitHub or this app.

## Files required in ONE ZIP

Use *provider-sourced actual records*, not reconstructed data generated by the model. All date columns are `YYYY-MM-DD` (US equity trading sessions). Fields below are case-sensitive.

**`security_master.csv`** (required)

```csv
security_id,ticker,valid_from,valid_to
```

- `security_id` is a permanent vendor-issued **security** identifier, not a ticker. An identifier must not be reused across different stocks. One security may have several ticker-history rows with non-overlapping, inclusive `valid_from`/`valid_to` intervals.
- Use `security_id=SPY, ticker=SPY` for the benchmark; blank `valid_to` means open-ended. For a delisted security, include its actual documented listing end.
- If an old ticker was later reassigned to an unrelated company, it **must have a different security_id**. Conflicting simultaneous ticker mappings are rejected.

**`price_history.csv`** (required)

```csv
date,security_id,adjusted_close,raw_close,volume
```

- `adjusted_close`: positive close adjusted using an appropriate **total-return methodology** for splits/distributions and comparability across time. Do not label unadjusted or partial vendor data as a total-return series.
- `raw_close`: the actual *contemporaneous* close on that day, used for historical minimum-price and dollar-liquidity tests, **not** for computing split-adjusted forward returns.
- `volume`: actual shares traded; missing may be blank, **never made zero**. A missing or ambiguous adjusted close is rejected, not interpolated.
- Every instrument's observation must map to an ID and trading interval in `security_master.csv`. Prices may not occur outside the archived SPY session calendar.
- A delisted security should stop receiving market bars when trading actually stops. **Do not forward-fill or artificially create prices after delisting.** Supply a documented terminal payoff when its test horizon spans that event.

**`membership.csv`** (required)

```csv
date,security_id,eligible
```

- Each dated snapshot must include **every stock eligible on that historical signal date**, including companies that later delisted or changed tickers.
- `eligible=true/false` should reflect the exact *historical strategy's investable universe or index membership*, not today's ticker list. `SPY` may not be an eligible stock.
- Missing snapshots for an actual tested signal date stop strict backtesting. Snapshot completeness **cannot be inferred** from checksums or row counts.

**`terminal_returns.csv`** (optional until a security delists during a tested horizon)

```csv
signal_date,security_id,asof_total_return,entry_total_return,event_date,source_reference
```

- Include one sourced record for **every affected signal date and security** for which a full 20-session (or configured horizon) terminal market price is unavailable.
- `asof_total_return`: full realized total return from the **signal day's close** through settlement and the requested horizon. `entry_total_return`: full realized return from **next session's close** (if actually fillable) through settlement/horizon.
- `event_date`: documented delisting/merger/bankruptcy settlement event inside the signal horizon. `source_reference`: specific vendor record reference, not the literal word "archive".
- Returns must be finite and >= -100%. A zero recovery is `-1.0`, but do not impose -100% without evidence: mergers, cash buyouts, or bankruptcies can have different recoveries.
- If the terminal event falls outside the simulated horizon, the archive record is rejected. Selected positions without documented payoff produce an error, **not silently unused cash**.

**`financial_facts.csv`** (optional for richer SEC features)

```csv
security_id,filed,period_end,accession,revenue_usd,net_income_usd
```

- `filed` must be the original public filing date, not financial period end or the day you downloaded the archive; `accession` is the actual SEC filing accession identifier.
- Each amendment/restatement is a **separate row with its own later filing date**. The app recomputes historical quarterly metrics at each *filing vintage* and exposes them from the **next business session** only.
- Complete features need historical filing coverage, correctly aligned issuer-to-security mapping, and consistent units. Unsupported tags and missing filings stay missing/flagged, not invented.
- Historic SEC fact figures parsed from today's official SEC companyfacts retain original `filed` dates and are likewise recomputed at each publication vintage. Exact original dissemination-time verification would require additional independently archived records.

**`manifest.json`** (required, usually generated by script)

Contains `format: "ithaca-historical-v1"`, provider, source_reference, `price_basis: "total_return_adjusted_close"`, and SHA-256 hashes for every CSV. It guards against *unnoticed file changes after packaging*, **not** falsification or incomplete vendor coverage.

## How to import

1. Save your actual vendor-exported CSV files in `my_exports/` at your working directory. Check that licensing allows local analysis.
2. Build an integrity-checked archive from the repository root:

```bash
python scripts/build_historical_archive.py ./my_exports ./my_historical_market.zip --provider "Your vendor name" --source-reference "Original export/query reference and extraction date"
```

3. Optionally inspect the file offline:

```bash
python scripts/audit_historical_archive.py ./my_historical_market.zip
```

4. Launch Ithaca Quant v3.1, open **Walk-forward tests**, and upload `my_historical_market.zip` under **Point-in-time market archive**. Run the historical backtest. This route uses *only archive-supplied securities, prices, universe snapshots, and optional financial facts/payoffs*. It does not mix today's Yahoo listing results into the historical simulation.
5. Check the displayed date range, internal price gaps, adjusted-return outliers, missing volume, available terminal payoff rows, and source declaration. A valid ZIP **does not guarantee** authentic historical contents. For real evaluation, obtain and audit primary-source or reputable licensed records.

## Real-world limitations still requiring outside evidence

- Authentic complete delisted issuer/security coverage, historical index membership, correct corporate-action and payout adjustments, exact ticker/identifier history, and vendor provenance must be obtained from a suitable data source.
- A sparse archive of *only today's surviving companies*, even with correct hashes, **does not** fix survivorship bias. An archive without historical financial filings does not magically provide those factors.
- Exact order execution, spreads, borrowing, slippage, exchange halts, and market impact are not validated by a historical close-based simulation.
- Synthetic tests only validate code invariants, **not** stronger live-market forecasting accuracy.

Primary reference: SEC EDGAR API documentation https://www.sec.gov/search-filings/edgar-application-programming-interfaces. For archived stock security identity, corporate actions, and delisting histories, see WRDS/CRSP https://wrds-www.wharton.upenn.edu/ and Norgate https://norgatedata.com/data-package-faq.php.
